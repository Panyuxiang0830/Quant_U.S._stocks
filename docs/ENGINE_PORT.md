# 递归爆搜引擎迁移核对

本版以团队原因子包中的 FactorExpressionGenerator 和 Operators 为源，迁移生成与数值计算核心。默认入口 `usq mine` 已接入该核心；先前固定模板生成器仅保留为历史日志读取兼容。

## 保留的核心行为

- 基础字段、单字段/双字段生成、复杂度 1/2/3 的递归展开、候选名称和遍历顺序。
- 基础字段量纲注册、输出类别过滤、跨层算子限制。
- 高层双表达式按固定随机种子每层抽取至多 100 对的原有行为。
- 完整原算子实现，包括 rank 的 method=min、各 rolling min_periods、beta 与 alpha 定义。
- 支持已有因子宽表和核心表达式先成为基础字段，再继续组合。

`engine/operators.py` 与核对源文件逐字节一致。`engine/expression_generator.py` 仅修改模块导入位置，移除 import 语句后 AST 逻辑与源文件一致。参考夹具由未修改源码生成，包含三个复杂度的候选目录哈希、数量与顺序。

## 项目适配边界

本版没有照搬原 SearchPipeline 的整套数据路径、评价器和进程调度。`recursive.py` 负责美股字段、稳定证券 ID、既有因子和表达式树适配；递归计算采用原算子分派方式。`search.py` 将其接入本项目的批次进程、第一层评分及 SQLite 日志；复杂层与因子间评估由后续独立入口调用。

评价只使用 2015–2021 和已成熟的十日标签；候选评价进程不接收 2022 以后的数据。方向、筛选门槛和指标采用本项目当前配置。入选后再计算全期因子，供固定规则的验证和滚动模型使用。

进程初始化显式适配 fork/spawn，避免依赖父进程全局状态的隐式继承。恢复按候选日志而非手工跳过批号；记录生成器/算子哈希、数据哈希、标签结束日哈希、预算和种子。输出保存候选目录、逐批 CSV、全部试验日志和日 RankIC。

required_fields 是可配置的字段包含过滤，按表达式叶节点判断；不是按名称子串猜测是否包含目标字段。相同结构的不同源名称只评估一次，保留首次出现的源名称，并记录实际尝试数。

## 一致性验证与限制

测试比较原源码参考目录与移植后目录，核对复杂度 1/2/3 的表达式、顺序及数量；逐字节/AST 检查保护原算子和生成逻辑；数值测试核对排名并列、滚动预热、递归计算及无未来依赖；spawn 双进程与串行结果一致，断点恢复不重复评价。

该迁移保持原引擎的生成规则，不表示其量纲系统是严格物理量纲证明，也不表示已完成真实美股的大规模搜索或性能验收。小预算可能被低层候选占满；应检查实际目录，不能仅凭 complexity=3 声称所有三层表达式均已搜索。
